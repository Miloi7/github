## 0. 产品镜头与设计契约

### 0.1 产品镜头（先于像素）

按规范 0.1 推断：用户是正在写代码的前端开发者，带着一个名字（`grid`、`居中`、`addEventListener`）进来，目标是在 3 秒内拿到语法 / 取值 / 示例并复制，失败成本是转去 MDN。首读对象是**当前范围的名称与计数**，其次是条目的**名称 / 中文 / 摘要**与状态；主动作是**打开条目并复制示例**。因此密度必须紧凑（44px 行、12–13px、发丝线），因为 1274 条要对齐比较；状态与热度是第二层信息，不能压过名称。桌面是五列索引 + 右抽屉，移动是两行索引 + 全屏详情 + 筛选 sheet。
**假设标注**：未做用户访谈；用户画像来自规范 G1/G2/G3。如真实用户以「按分类浏览」为主而非「带名字搜索」，H4 的优先级需上调，H3 的优先级可下调。

### 0.2 设计契约（本轮验收用，不重做视觉系统）

| 项 | 契约 |
|---|---|
| 用户 + 任务 | 前端开发者：按名字或中文概念查一条，拿到签名/取值/示例并复制 |

## 1. 结论

### needs_revision（HOLD）

**一句话总评**：读数条、发丝线行视图、按语种自适应的抽屉与深色代码板已经形成明确的产品识别度，但**状态轴与搜索的可解释性还没有达到「可信参考工具」的成品线**——32 条「已废弃标签」被标成「标准」、40/41 条搜索结果没有任何可见命中、91 条「高频」在列表和卡片里没有文字标记。

**为什么不是 pass**：这不是「再抛光一下」的问题。参考工具的第一资产是**口径可信**：同一行不能既写「已废弃标签」又写「标准」；搜索不能给 41 条结果却让 40 条看不出为什么相关；91 条高频不能只有一个没有图例的绿点。三处都直接影响用户是否继续信任这个站。

**为什么不是重做**：视觉系统本身成立，且有几处是真正的产品资产（见 §4）。不需要换字体、换色板、换布局。需要修的是**状态契约、数据呈现 fallback、搜索理由、5 个交互可达性**；修完后这套视觉可以原样保留。

### 1.1 对「精美 / 高密度 / 非模板感」三个目标的判定

| 目标 | 判定 | 依据 |
|---|---|---|
| **精美** | **接近成品，3 处未完成** | 读数条、行视图、深色代码板、支持条已经成立；帮助面板的键位列/裁切、抽屉头动作组悬空、JS 型号行下方 240px 空白，是「没做完」而不是「不够花」 |
| **高密度** | **骨架达标，被数据呈现拖累** | 44px 五列、1274 行、发丝线都成立；但 602 条把同一句话放进两列（H2）、598 条「标准」逐行占像素（H1），密度被无效字符吃掉 |
| **非模板感** | **主体成立，局部回退** | 门户的 1274 读数条、语种字形卡、按语种自适应的抽屉、深色代码板都不是模板能生成的；但「标准」刷屏、重复列、帮助面板的散列键位会让人想起通用后台模板 |

## 2. 问题清单（按严重度）

> 以下 1 / 6 / 7 / 3 条均已在截图、DOM 或数据中复现；不含「我觉得不够高级」类意见。L 级是可在下一轮修的精度问题；若决定不修，请在发布记录里显式标注。

### 2.1 Blocker（1 条）

#### B1 · 32 条「已废弃标签」被标成「标准」，已废弃筛选漏数

- **现象**：`center` 的面包屑是「首页 › HTML › 已废弃标签」，中文名是「（已废弃）内容居中」，但标签行显示「标准」，名称没有删除线；「已废弃」状态筛选只有 16 条（15 obsolete + 1 deprecated），这 32 条不会出现在「已废弃」筛选里。列表页同一行于是出现「H · 已废弃标签 …… 标准」。
- **证据**：
  - `screenshots/09-search-1440.png` 第 8 行 `center`：分类列为 `H · 已废弃标签`，右端状态为 `标准`，名称无删除线。
  - 复现 `#/html/center`：`.rb-drawer__crumb` = `首页›HTML›已废弃标签`；`.rb-drawer__tagrow` = `标准 标签`；`getComputedStyle(.rb-drawer__title).textDecoration = none`。
  - 数据：`data/html-*.js` 中「已废弃标签」分类 32 条全部 `status:"standard"`（`center`、`font`、`strike`、`marquee`…）；`js/data.js:31-36` 的 `normOf` 因此返回 `standard`。
  - 筛选计数：`js/render.js:490-501` 用 `C.counts.byNorm.obsolete + deprecated` = 16。
- **违反**：规范 0.2「状态是两个维度」、2.4 A（`obsolete` 显示「已废弃」+ 名称删除线）、7.7（状态不能只靠颜色，文字必须一致）、9 微文案、10.3 数据风险。核心是**参考工具的状态必须可信**。
- **修法**：在 `normOf` 优先按「HTML 的 `cat === 'deprecated'`（已废弃标签）」或 zh 前缀「（已废弃）」归为 `obsolete`；或在数据层修这 32 条的 `status`/`statusLabel`。同步：
  - 状态轴 `obsolete` 15 → 47，`standard` 598 → 566；
  - 状态筛选「已废弃」16 → 48（47 + 1 deprecated），「标准」566；
  - 门户读数条 `598 规范状态` 同步为「566 标准」；
  - `center` 等名称加删除线，tag 行显示「已废弃」。
  > 这是数据/规范事实表的冲突，不是纯 CSS 问题；发布前必须产品裁决一个口径，不能三处各说各话。
- **验收**：`#/search?q=center` 行与抽屉都显示「已废弃」+ 删除线；状态筛选「已废弃」显示 48（或裁决后的数）；`#/html` 已废弃标签分类 32 条的 `_norm` 全为 `obsolete`；全站不再出现「已废弃标签 · 标准」。

### 2.2 High（6 条）

#### H1 · 598 条「标准」被逐行渲染，状态列时有时无

- **现象**：列表每行右端显示 10px 灰字「标准」（全站 598 条：`#/all` 实测 `.rb-status-plain` = 598；`#/css` 498 条、`#/html` 100 条 standard 行显示，`#/html` 的 43 条 common 行空白）。热度轴条目（`common`/`hot`/`rare`，共 501 条）没有规范状态，状态列留空；于是同一个 HTML 分类里，`base` 行显示「标准」，相邻的 `!DOCTYPE`/`html`/`head` 行空白。卡片视图的标准卡同样在右下角重复「标准」；移动端标准行行尾也重复。用户无法判断「空白」是状态差异还是渲染缺失。
- **证据**：
  - `screenshots/03-browse-all-dark-1440.png`、`04-browse-css-light-1440.png`、`11-mobile-browse-390.png`、`14-cards-view-1440.png` 的状态列。
  - 复现 `#/all`：`document.querySelectorAll('.rb-status-plain').length = 598`；`.rb-badge` = 175（全部是实验性/非标准/已废弃，没有一个「标准」徽章）；`#/html` 首屏只有 `base` 行出现「标准」。
  - `js/render.js:47-48`（standard 返回纯文本）；`css/components.css:434-442`（10px mono fg-3）；`js/data.js:31-36`（common/hot/rare → `none`，不渲染）。
- **违反**：0.3-6「默认态沉默」、2.4「598 条标准不画徽章，界面因此安静」、5.6「`--standard` 不渲染」；10.2 的「不显示徽章」字面通过，但 2.4 又写「纯文本」——**规范自身冲突**，实现选择了「纯文本」，结果既占了像素又不一致。
- **修法**：采用「沉默」读数：`normBadge` 对 `standard` 返回空字符串，列表/卡片的状态列**只放异常态徽章**（实验性/非标准/已废弃）。详情页如需要状态，放在标题副行（`显示类型 · 标准`，11px）或抽屉头（`CSS · 布局与定位 · 标准`），不要和标签混在同一行。若产品坚持保留「标准」文字，必须让**每一行都有状态**并在列表头解释列含义；当前「半列空白」不可接受。
- **验收**：`#/all` 的 `.rb-status-plain` = 0（或 1274 且列表头有说明）；`#/html` 不再出现 `base` 孤立「标准」；卡片视图 0 个「标准」；详情标准态不再出现「标准 可动画 标签」三连。

#### H2 · 602 条条目把同一句话放进两列（JS 459 + HTML 143）

- **现象**：
  - `#/js/dom` 每一行：名称 `querySelector`，中文名列 `querySelector`，摘要列才是真信息；**459/459 条 JS 的 `zh` 与 `name` 完全相同**。
  - `#/html` 每一行：`!DOCTYPE | 文档类型声明 | 文档类型声明`；**143/143 条 HTML 的 `summary` 与 `zh` 完全相同**。
  - 建议面板同样把 JS 名称显示两次；`center` 的 zh 与 summary 都是「（已废弃）内容居中」，在 09 里同一行出现两次。
- **证据**：
  - `screenshots/09-search-1440.png` 第 8 行 `center`：`（已废弃）内容居中` 在中文列与摘要列重复。
  - `screenshots/08-detail-js-let-1440.png`：抽屉标题 `let`，副标题又是 `let · MDN ↗`。
  - 复现 `#/js/dom` 前 3 行：`let | let | 声明块级作用域的局部变量…`；`#/html` 前 3 行：`!DOCTYPE | 文档类型声明 | 文档类型声明`。
  - 数据统计：JS `zh===name` 459/459；HTML `summary===zh` 143/143；CSS 0/672。
  - `js/render.js:324-326`（三列都无条件渲染）；建议面板 `js/render.js:462-468`（名称 + `zh || summary`，JS 的 zh 等于名称）。
- **违反**：0.3-2「用发丝线分栏而不是卡片堆叠」的密度承诺、2.7「中文说明用 sans、英文标识用 mono」的角色分工、4.2 五列各司其职。用户看到的不是「名称/中文/摘要」，而是「名称/名称/摘要」和「名称/中文/中文」——这是全站最像模板/数据绑定失败的一处，且覆盖 47% 条目。
- **修法**：在渲染层做 fallback，不改数据文件：
  - `zh === name`（或仅大小写/空格差异）→ 中文列渲染 `summary` 首句或 `aliases[0]`；没有则隐藏该列并让摘要列吃掉空间；
  - `summary === zh`（HTML）→ 摘要列渲染 `desc` 首句；没有则 HTML 行/卡隐藏摘要列；
  - 建议面板、卡片、抽屉副标题走同一 fallback；
  - 保留 1 行截断 + `title`。
- **验收**：`#/js/dom` 前 10 行 `name ≠ zh`；`#/html` 前 10 行 `zh ≠ summary`；`#/search?q=居中` 的 `center` 行不出现两次「（已废弃）内容居中」；建议面板 JS 行不再重复名称。

#### H3 · 热度轴在列表/卡片几乎不可读：91 高频没有「高频」徽章/图例，卡片 0 标记

- **现象**：91 条 `hot` 行只有名称左侧 6px 薄荷方点；**列表页 `.rb-badge--hot` = 0**；卡片视图 `card()` 不加 `is-hot`，复现 `#/js/dom` 45 张卡里 0 个热度标记；页面没有图例解释「绿点 = 高频」；`推荐` 排序按 语种→分类→`order`→名称，首行是实验性 `anchor-name`，并不优先高频。
- **证据**：
  - 复现 `#/js/dom`：8 个 `.rb-row.is-hot`，0 个 `.rb-badge--hot`；切卡片后 45 张卡、0 个 `.rb-card.is-hot`、0 个热度点/徽章。
  - 复现 `#/all`：91 个 `.rb-row.is-hot`、151 个 `.rb-row.is-rare`、175 个 `.rb-badge`（全是 exp/nonstd/obs）。
  - `js/render.js:57-59`（`heatBadge` 只在抽屉 `:884` 调用）；`js/render.js:332-345`（卡片无 hot 类）；`js/data.js:236-246`（`compareRecommended`）。

- **违反**：2.4 B（`hot` = 6×6 实心方点 **+ 徽章「高频」**）、5.6（`--hot` 实心薄荷徽章，全站唯一实心彩徽）、10.2「91 条高频用实心薄荷徽章」、0.3-1「颜色是信息」——当前绿点没有文字，用户无法解码。5.5 的卡片 meta 行没有列热度位，是规范缺口；但 0.2 的热度轴与 10.2 的 91 条徽章不能只在行视图成立。
- **修法**：

  - 卡片补 `is-hot`/`is-rare` 或徽章，保证卡片视图不丢状态。
  - `推荐`：若产品要真正的「推荐」，先按 `_heat`（hot→rare→normal）再分类/order；若不改排序，把「推荐」改名为「默认」，避免「推荐」暗示策展而实际是分类顺序。不要把「分类」和「推荐」做成两个几乎相同的选项而不解释。
- **验收**：`#/js` 列表 91 行有可见「高频」徽章或图例；卡片视图 hot 可见；`document.querySelectorAll('.rb-badge--hot').length > 0` 在列表/卡片；排序文案与行为一致。

#### H4 · 搜索 41 条结果中 40 条没有任何命中标记，建议面板被弱匹配挤占

- **现象**：`#/search?q=居中` 41 条，只有 `center` 有 2 个 `<mark>`；其余 40 条的名称/中文/摘要都没有高亮，因为匹配发生在 `keywords`/`values`/`desc`（`align-items` 的 keyword「居中」、`margin` 的 keyword、`-webkit-mask-position` 的 values 等）。用户看到 `align-items`/`margin`/`place-items` 排在前 7，却不知道它们为何相关；字面 `center` 排第 8。建议面板输入 `disp` 时，前 8 条里真正与 `disp` 强相关的只有 `display`/`dispatchEvent` 两条；`transition-behavior`、`-webkit-appearance`、`addEventListener`、`-moz-outline-radius-topleft/topright`、`text-decoration-skip` 与输入没有可见关联或只有很弱的关联。首页热门入口 `#Array.map` 在数据中无同名条目，点击落到「高阶函数 HOF」。
- **证据**：
  - `screenshots/09-search-1440.png` 第 1–7 行无 mark，第 8 行 `center` 有 mark。
  - 复现 `#/search?q=居中`：`rows=41`，`noMark=40`；首 10 条 `align-items|0, margin|0, margin-inline|0, margin-left|0, margin-right|0, place-items|0, text-align|0, center|2, background-position|0, text-box-trim|0`。
  - 复现建议面板 `disp`：8 行；第 3–8 行为弱匹配。
  - 复现 `#Array.map`：`#/search?q=Array.map` 只返回 1 条「高阶函数 HOF」；数据中无 `Array.map`（有 `map`、`Array.from`、`Array.of`）。
  - `js/search.js:122-184`（keywords/values/desc 命中分数）；`js/render.js:458-469`（建议只高亮 name/zh）；`js/render.js:423-432`（HOT_SUGGEST）。
- **违反**：4.3 的命中高亮承诺、0.1 G1「3 秒找到」、9「热门入口」；8.4 只允许高亮 name/zh/summary，但没有规定 keyword/values/desc 命中时如何解释（规范缺口），结果是 40 条结果不可解释。排序本身是分数递减（70 的关键词命中排在 55 的中文名命中之前），不是 bug；问题是**可见字段没有命中理由**，用户无法验证相关度。
- **修法**：

## 4. 亮点（最多 5 条，均说明「为什么成立」）

1. **门户读数条**（`screenshots/01-portal-dark-1440.png`、`02-portal-light-1440.png` 中部）：`1274` 用 56px mono 只出现一次，其余 5 格 20px，格间 1px 发丝线，首格 1.5fr 加宽。它不是「数据看板」，是「仪器主表」；数字大小对应信息重要性，而不是平均分配卡片。**保留**。
2. **行视图的五列发丝线节奏**（`screenshots/03`、`04`）：44px 行、240/132/1fr/108/64、2px 语种轨、无卡片边框、无阴影。名称 mono 13 与中文 sans 12 的对比让「扫读 + 比较」成立；这是全站最像「规格书」的地方。**保留**（只需清掉 H1 的 598 条标准字）。
3. **抽屉的语种自适应章节 + 支持条**（`screenshots/05/07/08` 的章节结构；支持条为复现 `#/css/display` 4/4、`#/css/max-lines` 0/4）：CSS 8 节、HTML 6 节、JS 4 节，空章节不占位；版本号/`✗`/`preview`/`—` 三态用字符 + 3px 色条双编码，不靠红绿整块。**保留**。
4. **深色代码板作为双主题常量**（`screenshots/05`、`06`）：浅色界面里代码块仍是 `#12151A`，行号、字符数、复制钮、语法色一套；这是「工程手册里贴的深色端子图」的识别特征，也避免了浅色语法高亮的维护成本。**保留**。
5. **语种卡的字形 + 2px 色条 + 计数**（`screenshots/01`、`02`）：`< >` / `{ }` / `( )` 三个字形替代 emoji，40% 顶条只占一角，卡片不整块着色；它把「三种语言」变成可识别的品牌记号，而不是三张通用入口卡。**保留**。

## 5. 明确「无需修改」的争议点（防止下游过度返工）

9. **列表头「排序 推荐」「1 项筛选」是 4.2 的读数摘要，不是重复控件**：不要删除；要改的是「推荐」的语义（H3）。
10. **移动端行尾用状态代替 `▸`**（`11`）：整行可点，状态占右侧是合理替代；不要再加 `▸` 与状态争位。
