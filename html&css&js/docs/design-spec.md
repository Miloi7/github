### 0.2 数据事实（直接决定界面结构，先读这一节）

| 事实 | 数值 | 对设计的影响 |
|---|---|---|
| 总量 / 分片 | 1274 条 / 21 个 JS 分片（共约 1.49MB，单分片最大 123KB） | 首屏不阻塞数据；骨架屏必须存在 |
| 语种分布 | CSS 672、HTML 143、JS 459 | 三语种不是平行关系，CSS 是主战场：默认落地语种 = CSS |

| **JS 无 syntax** | 459 条 `syntax` 全为空，无 `values`/`notes`/`browser` | JS 详情的示例代码是**唯一主体**，代码块需放大；不得出现空的"语法"章节 |

| 名称长度 | 中位 13 字符，p99 = 37，最长 68（`Set.symmetricDifference / isSubsetOf / …`） | 名称列必须可截断 + 可换行，行高不能写死为单行高度 |
| 摘要长度 | 中位 15 字，p99 = 64，最长 90 | 卡片摘要 2 行截断；行视图摘要 1 行截断 |
| 示例长度 | 中位 59 字符，最长 198 | 代码块默认高度够用，超长内部滚动 |
| 语法长度 | p99 = 149，最长 1972 | 语法块必须可横向滚动，禁止撑破抽屉 |
| `mdn` 缺失 | 108 / 1274 | MDN 按钮是可选元素，缺失时不渲染 |
| `icon` 字段是 emoji（JS 分类） | 25 处 | **界面不使用 emoji**，分类图标改用内联 SVG 映射（附录 B） |
| `--*` 自定义属性 | 仅 1 条 | 不做"CSS 变量专区" |

### 0.3 六条设计原则（后续所有取舍以此裁决）

1. **颜色是信息，不是装饰。** 除品牌薄荷绿（只用于交互态与"高频"）外，所有色彩都编码真实数据：语种、规范状态、匹配命中。没有"为了好看"的渐变。
2. **用发丝线分栏，而不是用卡片堆叠。** 1px 细线 + 留白建立结构，取代"大圆角 + 投影 + 卡片套卡片"的通用后台观感。密度由此提升约 35%。
3. **数字用仪表读数的呈现方式。** 所有计数、版本号、序号用等宽体 + `tabular-nums`；数量越大，字号越大。`1274` 是品牌资产，不是一个普通数字。
4. **悬停不位移。** 1274 项的高密度网格里，`translateY(-1px)` 会造成整页"呼吸抖动"。悬停只改边框色与底色（见 6.2）。
5. **键盘路径是主路径，鼠标是加速器。** 搜索 → 建议 → 详情 → 上/下一条 → 关闭，全程可键盘完成，且焦点可见、可预测。
6. **默认态沉默，异常态发声。** 598 条"标准"不显示徽章；只有实验性、非标准、已废弃、高频才占用视觉像素。

### 1.1 名称

| 层级 | 内容 |
|---|---|
| 品牌名（中文） | **速查台** |
| 品牌名（英文） | **REFBENCH** |

| 浏览器书签默认名 | `前端速查大全`（用户可识别性优先，品牌名次之） |

> 命名意图：**bench = 工作台**。1274 个零件摊开在同一张台面上，每条都带型号、规格与兼容性读数。它不是"资料库"，是"仪器"。

### 1.2 气质

**关键词**：哑光 · 克制 · 精密 · 高密度 · 可读的代码感 · 规格书（spec sheet）

一句话描述：

> 一块哑光石墨面板，上面用等宽字体刻着 1274 行读数；薄荷绿只在"你正指向这里"时亮一下。

**要**：发丝线、编号章节、等宽数字、纸白/石墨双底色、极短动效、克制的单一强调色。
**不要**：霓虹发光、渐变文字、毛玻璃大面积铺底、大圆角卡片阵列、emoji、插画、阴影堆叠、彩色按钮满屏。

### 1.3 Logo：三栈刻度盘

**概念**：三条长度不同的横向刻度轨，代表三种语言的"信息深度"；每轨右端一个小方点，是光标的抽象。整体封装在一个圆角方牌里，像仪器面板上的铭牌。

```
 24×24 画布（示意，非等比）

 ┌────────────────────────┐
 │  ━━━━━━━━━━━━ #        │   ← 轨1  x=6  y=7.00   w=12   HTML
 │  ━━━━━━━━━ #           │   ← 轨2  x=6  y=11.25  w=9    CSS
 │  ━━━━━━ #              │   ← 轨3  x=6  y=15.50  w=6    JS
 └────────────────────────┘

 牌：rect x=2 y=2 w=20 h=20 rx=5 · stroke 1.25 · 无填充
 方点：每轨右端 1.5×1.5 · rx=0（方角，区别于圆形装饰）
```

**规格**

| 项 | 值 |
|---|---|
| 画布 | 24 × 24，`viewBox="0 0 24 24"` |
| 外牌 | `rect x=2 y=2 w=20 h=20 rx=5`，`stroke` 1.25，无填充 |
| 轨 1 | `x=6 y=7 w=12 h=1.5 rx=.75`，HTML 色 |
| 轨 2 | `x=6 y=11.25 w=9 h=1.5 rx=.75`，CSS 色 |
| 轨 3 | `x=6 y=15.5 w=6 h=1.5 rx=.75`，JS 色 |
| 光标方点 | 每轨右端 `rect 1.5×1.5`，位于轨的垂直中心，`rx=0`（方角，区别于圆形装饰） |
| 安全边距 | 2px（牌外） |
| 最小尺寸 | 16px（此时隐藏外牌，仅三轨 + 方点） |
| 单色版 | 全部 `currentColor`，用于页脚与打印 |
| 动效 | **无**。Logo 不旋转、不发光、不带描边动画 |

**用法**：顶栏 22px（牌 + 三轨） + 文字标；favicon 32px 单文件内联 data-URI；Portal 语种卡不使用 Logo（用 `< >` `{ }` `( )` 三个字形，见 4.1）。

**文字标**：`速查台` 用 13/18 · 600；其右 `REFBENCH` 用 10/14 · 500 · `letter-spacing: .18em` · `--fg-3` · 大写。

### 1.5 与现状（CSScz）的差异

| 维度 | 现状 CSScz | 本方案 | 理由 |
|---|---|---|---|
| 色彩 | 霓虹青 `#67e8f9` + 紫 `#a78bfa` 双强调 + 发光 | 哑光石墨 + **单一**薄荷绿 `#35E0A1`（仅交互态） | 双强调色在大密度界面里互相争抢注意力 |
| 结构 | 大圆角卡片（13/18px）+ 柔和投影 | 1px 发丝线 + 行式索引表 + 8px 圆角 | 提升 35% 信息密度，去除"后台模板"观感 |
| 首屏 | 60px 渐变 hero 标题 | 34px 平铺标题 + 六格读数条 | 从"落地页"变成"仪表盘" |
| 悬停 | 卡片上浮 2px + 投影 | 仅边框 / 底色变化 | 1274 项网格中位移会造成视觉抖动 |
| 主视图 | 卡片网格 | **行视图为主**（名称/中文/摘要/分类/状态五列），卡片为次 | 对齐的列让"扫读 + 比较"成为可能 |
| 背景 | 网格线 + 径向光晕 | 纯色 + 可选 1% 噪点（见 8.6） | 装饰性背景与代码阅读抢对比度 |
| 圆角 | 6/9/13/18/26 | 2/4/6/8/10/14/999 | 全站最大 14，接近"印刷品"而非"App" |

### 2.4 状态：两套正交的视觉语汇

数据里 `status` 混装了两个维度，界面必须拆开：

**A. 规范状态（规范轴）——出现在行/卡右侧的状态位**

| status | 显示文本 | 视觉 | Dark | Light |
|---|---|---|---|---|
| `standard` | `标准` | **纯文本，无边框**（默认态，沉默） | `--fg-3` | `--fg-3` |
| `experimental` | `实验性` | 填充徽章 + 1px 同色边框 | 底 `#2D2B3C`，字 `#D6C6FF`（8.79） | 底 `#F0EBFC`，字 `#6D3FD1`（5.48） |
| `nonstandard` | `非标准` | 透明底 + **虚线**边框 | 边 `--line-3`，字 `#9AA1AC`（6.29） | 边 `--line-3`，字 `#5A616B`（5.37） |
| `obsolete` / `deprecated` | `已废弃` | 透明底 + 实线边框 + **名称加删除线** | 边 `--line-2`，字 `#8C8F95`（5.05） | 边 `--line-2`，字 `#6D6F74`（4.81） |

**B. 热度（热度轴）——出现在名称左侧的 6px 方点**

| status | 标记 | 说明 |
|---|---|---|
| `hot` | **6×6 实心方点**，`--acc` + 徽章 `高频`（实心薄荷底、深色字 11.09:1） | 91 条；这是最值得优先看的集合 |
| `common` | 无标记 | 259 条（HTML 常用 43 / JS 普通 216） |
| `rare` | 4×4 空心方点（1.5px 边），`--fg-3` | 151 条；最弱的标记，不用 `--fg-4`（对比度不足以承载信息） |
| `deprecated` | 同 `obsolete` 的处理 | 1 条 |

> 设计意图：598 条"标准"不画徽章，界面因此安静；91 条"高频"用唯一的强调色——让强调色本身就带信息量。

### 2.7 字体与字号阶梯

**没有外链字体**，因此识别度必须由「字号反差 + 字距 + 字重 + 等宽数字」承担。

```css
--font-sans: -apple-system, BlinkMacSystemFont, "Segoe UI Variable Text", "Segoe UI",
             "PingFang SC", "Hiragino Sans GB", "Microsoft YaHei UI", "Microsoft YaHei",
             "Noto Sans SC", system-ui, sans-serif;
--font-mono: "Cascadia Mono", "Cascadia Code", "JetBrains Mono", "SFMono-Regular",
             Consolas, "Liberation Mono", Menlo, monospace;
```

> Windows 优先命中 `Segoe UI Variable Text`（Win11）/ `Segoe UI`（Win10），中文回落 `Microsoft YaHei UI`；等宽优先 `Cascadia`（Win Terminal 自带）→ `Consolas`（必命中）。禁止 `@font-face`。

|---|---|---|---|---|---|

**规则**

- 所有数字（计数、版本、序号、百分比）加 `font-variant-numeric: tabular-nums`，保证纵向对齐。

- 大写微标签不上 `text-transform` 于中文（中文无大写），仅用于拉丁字母标签（`SPEC`、`REFBENCH`、`CSS`）。
- 中文不使用 `font-weight: 700` 以上（YaHei 会糊），最大 600。

## 3. 栅格与断点

### 3.1 四个断点

| 断点 | 视口 | 形态定位 | 关键变化 |
|---|---|---|---|
| **XL** | ≥ 1440 | 完整工作台 | 固定侧栏 + 五列行视图 + 720 抽屉 |
| **L** | 1024–1439 | 紧凑工作台 | 侧栏收窄至 236 + 三列 + 640 抽屉 |
| **M** | 768–1023 | 平板 | 侧栏消失 → 分类横向 chip 条；两行行视图；抽屉全宽 |
| **S** | < 768 | 手机 | 单列两行；无工具栏（并入顶栏）；底部 sheet |

断点用 `min-width` 升序书写（移动优先），单位 `px`，不使用小数断点。

### 3.3 栅格与列宽计算

**行视图（主视图）列定义**

| 列 | XL | L | 说明 |
|---|---|---|---|
| 语种/强调轨 | 2 + 10 | 2 + 10 | 2px 左轨（语种色，仅行首）+ 10px 内缩 |
| 名称 | 240 | 208 | mono 13 · 500 · 单行截断 + `title` |
| 中文名 | 132 | 116 | sans 12 · `--fg-2` |
| 摘要 | `1fr`（≥180） | `1fr`（视口 ≥1200 显示，<1200 隐藏） | sans 12 · `--fg-3` · 单行截断 |
| 分类 | 108 | 96 | 语种色 4px 点 + 11px 名 |
| 状态 | 64 | 64 | 右对齐 |
| 热度点 | 16 | 16 | 6px 方点 |

- 列间距 `--sp-7`（16px）；行左右 padding 16；行间用 `--line-1` 分隔，**不画卡片边框**。
- 计算校验（XL@1440）：`1440 − 64(padding) − 272(侧栏) − 28(gutter) = 1076`；固定列合计 `2+10+240+132+16×4+108+64+16 = 636` → 摘要列宽 **440**。
- 计算校验（XL@1680 上限）：`1680 − 64 − 272 − 28 = 1316` → 摘要列 **680**（超 480 时摘要列 `max-width: 480px`，剩余空间留在行尾，避免行长过宽）。

**卡片视图列**

- `grid-template-columns: repeat(auto-fill, minmax(300px, 1fr))`，`gap: 12px`。
- XL@1440：`1076 / 3 = 348`（3 列）；XL@1680：`1316 / 4 = 320`（4 列）；L@1280：`972 / 3 = 316`；M@900：`860 / 2 = 424`；S：1 列。
- 卡片最小高 118（名称 20 + 中文 18 + 摘要 36 + 元信息 24 + padding 24 ≈ 122，允许 ±）。

**首页 12 列栅格**（仅首页使用）

- XL：`grid-template-columns: repeat(12, 1fr)`，`gap: 16px`；语种卡各占 4 列；分类索引每组 12 列内分 4 列（每组 3 行）。
- L：语种卡 12 列内 4/4/4 保持不变；分类索引改 3 列。
- M/S：全部单列堆叠，间距降为 12/10。

**抽屉内部两栏**

| 断点 | 侧栏（章节刻度） | 正文 |
|---|---|---|
| XL | 40（`§01…§08` 纵向刻度） | 1fr，最大 62ch |
| L | 36 | 1fr |
| M/S | 取消侧栏 → 顶部横向 chip 条 36 高 | 全宽 |

- **滚动容器**：桌面端是 document（不是内部容器），保证 `Ctrl+F`、`Home/End`、锚点跳转、滚动条行为都符合直觉。
- 工具栏隐藏规则：`scrollY > 120 && 向下滚动 > 8px` → `translateY(-48px)`；向上滚动立即恢复。`prefers-reduced-motion` 下直接切换 `visibility`，不做位移。
- 抽屉打开时：`document.body` 加 `overflow:hidden` + `padding-right: 滚动条宽度`（防抖动）；关闭后恢复并还原滚动位置。
- 侧栏独立滚动：`overscroll-behavior: contain`，避免滚到底后带动页面。
- 移动端抽屉：`height: 100dvh`（不用 `100vh`，避免地址栏溢出）。

### 6.4 焦点管理

1. **跳转链接**：页面首个可聚焦元素 `<a href="#main">跳到主内容</a>`，聚焦时从顶部滑下（`--sh-2`，`z-index:var(--z-skip)`）。
2. **抽屉**：打开 → 记录 `document.activeElement` → 焦点移到抽屉标题（`tabindex="-1"`）→ 陷阱；关闭 → 焦点还原到触发行（若该行已被筛选隐藏，则回到搜索框）。
3. **建议面板**：焦点始终留在 `input`，用 `aria-activedescendant` 指向高亮项（不移动 DOM 焦点），保证输入不中断。
4. **筛选/排序 popover**：焦点进入菜单第一项，`Esc` 回到触发钮。
5. **Toast**：不获取焦点，只用 live region。
6. **主题切换后**：`document.activeElement` 不变（不要把焦点丢到 body）。

### 7.2 焦点可见性

- 全局 `:focus-visible` 规则统一，禁止任何 `outline: none` 而无替代。
- 焦点环 2px + 2px offset；与相邻元素的颜色差 ≥3:1（见 7.1）。
- 焦点不会落在不可见元素上：抽屉关闭后，若原触发行被隐藏，焦点回到搜索框（`aria-label` 提示"已回到搜索框"）。
- 滚动容器（代码块、语法块）设 `tabindex="0"`，并在焦点时显示 2px 环（否则键盘用户无法横向滚动）。
- 模态（抽屉/sheet）打开时，背景内容加 `inert`（不支持时用 `aria-hidden="true"` + `tabindex="-1"` 兜底）。

### 7.3 ARIA 与语义

| 组件 | 角色 / 属性 |
|---|---|
| 顶栏 | `<header>`；品牌区 `<a aria-label="回到首页 速查台">` |
| 搜索 | `role="combobox"` + `aria-expanded` + `aria-controls="suggest"` + `aria-autocomplete="list"` + `aria-activedescendant`；建议列表 `role="listbox"`，行 `role="option"` + `aria-selected` |
| 结果计数 | `<p role="status" aria-live="polite">32 条结果</p>`（只播报计数，不播报整表） |
| 语种切换 | `role="tablist"` / `role="tab"` + `aria-selected` + `aria-controls`；面板 `role="tabpanel"` + `aria-labelledby` |
| 分类导航 | `<nav aria-label="分类导航">` + `<ul>`；激活项 `aria-current="page"` |
| 行列表 | 容器 `role="list"`，行 `role="listitem"`；当前虚拟光标行 `aria-current="true"`；不要用真正的 `<table>`（列宽响应式变化，语义反而不稳） |
| 详情抽屉 | `role="dialog"` + `aria-modal="true"` + `aria-labelledby`（标题 id）；章节标题用 `<h2>`/`<h3>` 形成大纲 |
| 章节刻度 | `<nav aria-label="章节">` + 锚点链接 |
| 代码复制 | `<button aria-label="复制示例代码">`；结果用 `role="status"` |
| 浏览器支持 | `<dl>`：`<dt>Chrome</dt><dd>1</dd>`；不整洁的状态用 `<span class="sr-only">不支持</span>` 补充 |
| Toast | `role="status" aria-live="polite"`；错误用 `role="alert"` |
| 图标按钮 | 一律 `aria-label` + `aria-hidden="true"` 于 `<svg>` |
| 语言标注 | `<html lang="zh-CN">`；英文条目名与代码标识符用 `<span lang="en">`，避免中文 TTS 把 `display` 读成拼音 |

**文档大纲**：`h1`（首页）→ `h2`（区块/抽屉标题）→ `h3`（章节），不跳级。浏览页无 `h1` 时用视觉隐藏的 `h1`（"前端速查大全 · 浏览"）。

### 7.4 触控与命中区

- 触控目标 **≥44×44**（S 断点）。视觉尺寸可以 32，但命中区用透明 padding/伪元素扩展到 44。
- 行高 64（S）→ 整行可点；行内 `▸` 与行的点击行为一致（都打开详情），不设嵌套小按钮。
- 图标钮之间最小间距 8，避免误触。
- 底部 sheet 的「应用」按钮高 44，宽占满剩余空间。

### 7.5 动效、对比度与强制色的偏好适配

```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: .001ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: .001ms !important;
    scroll-behavior: auto !important;
  }
  /* 位移改为纯透明度变化；骨架静止 */
}
@media (prefers-contrast: more) {
  /* 边框统一升级：--line-1/2 → --line-3；--fg-3 → --fg-2；关闭 tint 底 */
}
@media (forced-colors: active) {
  /* 只依赖 border 与 currentColor；用系统色（CanvasText/Highlight）替代语种色条；
     状态徽章改为带文字的实线边框；预览区网格底纹关闭 */
}
```

- 不用 `scroll-behavior: smooth` 作为默认（会造成"滚动失控"），仅在返回顶部/章节跳转时临时启用，并在 `reduced-motion` 下禁用。
- 不支持 `prefers-contrast` 的浏览器保持默认，不报错。

### 7.6 文本缩放与重排（200%）

- 全站无固定 `height` 承载文字（用 `min-height` + `padding`）；行视图的行高改为 `min-height: var(--h-row)`。
- 200% 缩放（等价 1280px 视口 640px 内容宽）下：断言不出现横向滚动条；侧栏自动降级为 M 断点行为。
- 代码块允许横向滚动（代码语义要求不换行），但外层容器不得横向溢出。
- 中文与拉丁混排行高统一 1.65（正文 15/26），保证放大后不拥挤。

### 7.7 不以颜色为唯一编码

| 信息 | 颜色编码 | 冗余编码 |
|---|---|---|
| 语种 | HTML 橙 / CSS 靛 / JS 黄 | 字母 `H C J` 或字形 `< > { } ( )`；tab 有文字 |
| 规范状态 | 徽章色 | 徽章文字（标准/实验性/非标准/已废弃）+ 边框样式（实/虚/删除线） |
| 热度 | 实心/空心方点 | 「高频」徽章文字；「少见」有 `aria-label` |
| 兼容性 | 顶色条 | 版本号 / `✗` / `preview` / `—` 字符 |
| 命中 | 高亮底 | 加粗 |
| 当前项 | 左轨 + 底色 | `aria-current` / `aria-selected` |

### 7.8 屏幕阅读器友好细节

- 行列表读法：`display，显示，元素生成何种盒子，布局与定位，标准，高频`（用 `aria-label` 组合，避免听到 7 个独立片段）。

## 8. 性能与工程约束

### 8.1 预算

| 指标 | 预算 | 说明 |
|---|---|---|
| 首屏可见（骨架） | < 400ms | `index.html` + CSS 解析完成 |
| 首个可交互（列表可滚） | < 1.2s | 依赖 `meta.js` + 首个分片（≤126KB） |
| 全量数据就绪 | < 2.5s | 21 个分片共约 1.49MB（`file://` 下无网络延迟） |
| 搜索 → 列表刷新 | ≤ 60ms | 含高亮；1274 条字符串重建 |
| 筛选 → 列表刷新 | ≤ 40ms | 纯数组过滤 |
| 详情打开（含预览首帧） | ≤ 120ms | 预览 shadow DOM 懒创建 |
| DOM 节点总数（1274 行） | ≤ 12,000 | 每行约 9 个节点 |
| CSS 总量 | ≤ 64KB（未压缩） | 4 个文件 |
| JS 总量 | ≤ 48KB（未压缩） | 6 个模块 |
| HTML（含 SVG 精灵） | ≤ 40KB（未压缩） | 精灵约 7KB |
| 外部请求 | **0** | 无 CDN、无字体、无图片 |

### 8.2 数据加载

```
index.html
  ├─ meta.js          9 KB      ← 分类 / 计数 / 语种
  ├─ html-01..03.js   107 KB    ← 先到（3 片）
  ├─ js-01..08.js     286 KB    ← 8 片
  └─ css-01..10.js    1125 KB   ← 最大，最后（10 片）
```

- 全部 `defer`，保证顺序执行且不阻塞解析；`window.CS_DATA` 为聚合数组（分片自行 `push`）。
- 分片到达即用 `requestIdleCallback` 合并计数；**首次渲染只在 `meta.js` 之后发生**，避免"渲染 143 条再变 1274 条"的跳动。
- 分类导航在 `meta.js` 就绪后立即渲染（HTML 分类的计数先显示 `—`，随分片到达逐个补全，**不触发行高变化**）。
- 首屏默认语种 = CSS，但 CSS 分片最大：因此列表在 CSS 到达前显示 8 条骨架（高度与真实行一致），到达后一次性渲染。用户在 400ms 内看到的是稳定的框架，不是空白。
- `localStorage` 只存：主题、侧栏展开状态、最近搜索（≤5）、视图偏好。总量 < 2KB。

### 8.3 长列表渲染策略（1274 条）

**结论：不做虚拟滚动。** 用「一次性渲染 + `content-visibility` + 事件委托」。

| 手段 | 作用 | 数值 |
|---|---|---|
| 字符串拼接 + `replaceChildren` | 一次 DOM 写入，避免逐条 append | 1274 行 ≈ 380KB HTML 字符串，Chrome 实测 20–35ms |
| `content-visibility: auto` | 屏外行跳过布局与绘制 | 配合下一行 |
| `contain-intrinsic-size: 0 var(--h-row)` | 提供占位高度，滚动条不跳 | 44px（S 断点 64px） |
| 事件委托 | 1 个 listener 处理全部行 | `list.addEventListener('click', …)` + `closest('[data-id]')` |
| `contain: layout style paint`（行级） | `content-visibility:auto` 已隐含 layout/paint containment，二者**不同时加**（避免重复声明） | — |
| 命中高亮用 `<mark>` 字符串拼接 | 不额外遍历 DOM | 与行 HTML 一次生成 |
| 结果 > 500 截断 | 极端查询不炸 | 显示"已显示前 500 条" |

**为什么不用虚拟滚动**：1274 行 × 约 9 节点 ≈ 11.5k 节点，在现代浏览器中内存与布局成本可接受；而虚拟滚动会带来"`Ctrl+F` 找不到未渲染内容""锚点跳转失败""屏幕阅读器计数错乱"三类可访问性缺陷，与"离线速查工具"的定位冲突。

**降级预案**：若目标机器实测首屏渲染 > 80ms，改为**分批渲染**（每帧 200 行，`requestAnimationFrame` 链），保留全部 DOM，不改虚拟化。

### 8.4 搜索实现约束（影响 UI 的 BE 契约）

- 每条数据预生成 `haystack`：`name + zh + aliases + keywords + catName + tags + summary.slice(0,60)`，全部小写，构建一次（idle 时，约 8ms）。
- 评分：完全相等 100 / 前缀 80 / 词首 60 / 子串 40 / 单字符子序列 25（`bgc → background-color` 依赖此规则）；同分按 `hot`、语种顺序（CSS > HTML > JS）、`order` 排序。
- 查询分词：空格分隔，全部词都要命中（AND）。
- 高亮：只高亮**命中的原词**在 `name / zh / summary` 中的位置；`<mark>` 数量上限 6/行。
- 拼音/错拼：仅做 1 次编辑距离容错（`dispaly → display`），不做全量模糊（会伤害精确匹配的信任）。

### 8.5 CSS 与渲染优化

- 4 个样式文件（`tokens.css` / `base.css` / `layout.css` / `components.css`），`<link>` 顺序固定；不使用 `@import`（`file://` 下会造成串行请求）。
- 只对 `opacity` / `transform` / `color` / `background-color` / `border-color` 做过渡。
- `backdrop-filter` 仅顶栏，且 <1024 视口关闭（移动端 GPU 成本高）。
- 阴影全部用于浮层（3 个 token），列表内元素**零阴影**。
- 不使用 `box-shadow` 做悬停（重绘面积大）；用 `border-color`。
- `will-change: transform` 只在抽屉打开期间设置，关闭后移除（避免常驻图层）。
- 预览网格底纹用 `background-image: radial-gradient` + `background-size: 8px`，不生成图片。

### 8.6 资源与离线

- 图标：单个内联 `<svg><symbol>` 精灵——19 个界面图标 + 18 个分类图标 = 37 个 `<symbol>`，约 7KB；精灵放在 body 首个元素，`aria-hidden="true"`。
- favicon：`<link rel="icon" href="data:image/svg+xml,...">`（内联，避免 404）。
- 无图片、无视频、无字体文件。
- 全站禁止 `fetch`/`XHR`/`new Image()`/`@import` 指向外部；`file://` 下必须 0 请求（验收项）。
- 可选 1% 噪点（`feTurbulence` 转 data-URI）作为页面底纹——**默认关闭**，仅当性能预算有余量且用户未开 `prefers-contrast` 时启用。

## 附录 C 反模式清单

以下 15 条为本项目的明确禁止项，评审时逐条对照。

1. ❌ 渐变文字标题（`background-clip: text`）——辨识度靠字号与字距，不靠渐变。
2. ❌ 大面积霓虹发光（`box-shadow` 彩色外扩、`filter: drop-shadow`）。
3. ❌ 卡片 `translateY` 悬停位移。
4. ❌ 超过 14px 的圆角（除底部 sheet 的上圆角与圆形进度环）。
5. ❌ 给 598 条"标准"条目加徽章。
6. ❌ 列表中使用阴影表达层级（层级用底色档位 + 发丝线）。
7. ❌ 用 `--line-2` 作为输入框边框（对比度不足 3:1）。
8. ❌ 命中高亮改变字号或行高（导致重排抖动）。
9. ❌ 虚拟滚动（破坏 `Ctrl+F` 与读屏计数）。
10. ❌ 抽屉内使用 iframe 预览（加载闪烁、无法即时响应主题）。
11. ❌ 在界面上渲染数据里的 emoji 分类图标。
12. ❌ 主题切换时重建列表 DOM（会造成焦点丢失与闪烁）。
13. ❌ 用 toast 报告"复制成功"（用按钮内状态即可）。
14. ❌ 任意长度的进场动画（>320ms 一律禁止）。
15. ❌ 把筛选状态写进 URL（组合爆炸，且会让"分享链接"充满噪声）。
